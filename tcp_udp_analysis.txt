پروتکل TCP شامل موارد زیر  است:

اتصال‌گرا (قبل از ارسال داده، ارتباط برقرار می‌کند)
تضمین تحویل داده (در صورت گم شدن، دوباره می‌فرستد)
بسته‌ها به ترتیب دریافت می‌شوند
کنترل ازدحام دارد (سرعت را تنظیم می‌کند)
سرعت کندتر (به دلیل سربار اضافی)
اندازه هدر ۲۰ تا ۶۰ بایت
کاربرد برای انتقال فایل، وب‌گردی، ایمیل


پروتکل UDP شامل موارد زیر است:

بدون اتصال (داده را بدون مقدمه می‌فرستد)
تضمینی برای تحویل داده وجود ندارد
ترتیب بسته‌ها مشخص نیست
کنترل ازدحام ندارد
سرعت سریع‌تر (سربار کم)
اندازه هدر ۸ بایت
کاربرد پخش زنده، تماس صوتی، DNS


Streaming Video ----> UDP
سرعت و پخش بی‌وقفه مهم‌تر از از دست رفتن چند بسته است. اگر TCP استفاده شود، با هر بسته گم‌شده، پخش متوقف شده و بافرینگ ایجاد می‌شود

Streaming Video ----> UDP
سرعت و پخش بی‌وقفه مهم‌تر از از دست رفتن چند بسته است. اگر TCP استفاده شود، با هر بسته گم‌شده، پخش متوقف شده و بافرینگ ایجاد می‌شود

File Transfer (FTP) -----> TCP
انتقال فایل نیاز به تحویل کامل و بدون خطا دارد. حتی یک بسته گم‌شده می‌تواند فایل را خراب کند

DNS Query -----> UDP
درخواست DNS معمولاً یک بسته کوچک است. اگر پاسخ نیاید، کلاینت دوباره درخواست می‌دهد. سرعت بالا و سربار کم UDP برای این کار عالی است.

Web Browsing (HTTP/HTTPS) ----->  TCP
وب‌گردی نیاز به دریافت کامل و مرتب صفحه دارد. همچنین HTTPS برای رمزگذاری به ارتباط پایدار TCP نیاز دارد.

VoIP Call  ----->  UDP
تماس صوتی به تأخیر کم نیاز دارد. از دست رفتن چند بسته باعث اختلال جزئی در صدا می‌شود، اما قطع شدن مکالمه به خاطر تلاش برای ارسال مجدد (در TCP) غیرقابل‌قبول است.

Database Query  ---> TCP  
پرسش از پایگاه داده نیاز به دقت و صحت کامل دارد. حتی یک خطا در پاسخ می‌تواند باعث خرابی داده یا گزارش اشتباه شود.
